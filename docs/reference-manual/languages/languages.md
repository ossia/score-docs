# Languages

Find the syntax and runtime contract for code used in score. Each reference separates the underlying language from the objects, ports, variables or shader resources supplied by score. Process and device pages explain how to insert, connect and operate the corresponding component.

### JavaScript and QML APIs

The same language runs in several different contexts. Choose the API for the place where the code executes; a console script and an audio-process callback do not have the same responsibilities.

- [Process API]({{ site.baseurl }}/reference/languages/javascript-process.html): `Script`, ports, callbacks, timing, audio, MIDI and textures.
- [Editor API]({{ site.baseurl }}/reference/languages/javascript-editor.html): document editing, transport, devices, utilities and view automation.
- [Custom UI API]({{ site.baseurl }}/reference/languages/javascript-ui.html): control bindings, `ScriptUI`, persistent state and texture previews.
- [QML device API]({{ site.baseurl }}/reference/languages/qml-devices.html): device trees, mappings and protocol-specific callbacks.
- [QML transport API]({{ site.baseurl }}/reference/languages/qml-protocols.html): sockets, framing, HTTP, OAuth, OSC and MIDI payloads.

For editor workflow and examples, see [[Scripting]] and [[Custom UI]]. These are Qt-hosted scripts, not a browser or Node.js environment.

## GPU languages and shader formats

Start with [GLSL and Vulkan compatibility]({{ site.baseurl }}/reference/languages/glsl.html) for types, shader stages, standard functions and the distinction between user code and declarations generated by score. The formats below combine GLSL with a header that defines controls, resources and execution.

| Format | Execution model | Reference |
|---|---|---|
| ISF — Interactive Shader Format | Fullscreen fragment passes for images and video | [ISF and score extensions]({{ site.baseurl }}/reference/languages/isf.html) |
| CSF — score's compute extension | Compute dispatches over images, buffers and geometry | [CSF headers, resources and functions]({{ site.baseurl }}/reference/languages/csf.html) |
| Raw raster pipeline | Vertex and fragment stages for custom geometry rendering | [Raster interfaces and pipeline state]({{ site.baseurl }}/reference/languages/raw-raster.html) |
| Vertex Shader Art | Procedural points and lines generated in a vertex shader | [VSA inputs and shader contract]({{ site.baseurl }}/reference/languages/vertex-shader-art.html) |
| Geometry filter | Vertex-attribute callback applied by the downstream renderer | [Geometry-filter shader contract]({{ site.baseurl }}/reference/languages/geometry-filter.html) |

The [Graphics pipeline]({{ site.baseurl }}/in-depth/video.html) explains how these processes connect. The [Shader cookbook]({{ site.baseurl }}/in-depth/shader-cookbook.html) gives recipes that use the references. A Vulkan-compatible shader language does not mean that every GPU or rendering backend supports every resource or extension.

## Rule-based graphics

- [EisenScript]({{ site.baseurl }}/reference/languages/eisenscript.html): transformations, recursive rules and weighted alternatives for Structure Synth geometry.
- [Context Free / CFDG]({{ site.baseurl }}/reference/languages/context-free.html): shape grammars for image generation.

These languages build geometry or images from rules; they are not per-sample audio languages or per-frame GPU shaders.

## External interpreters

[External scripts]({{ site.baseurl }}/reference/languages/external-scripts.html) links the Python, POSIX shell, Bash, Zsh, Fish, PowerShell and Cmd references used with [[Shell command]]. These interpreters must be installed separately: invoking them is not the same as embedding their language runtime in score.

## Which documentation applies?

Use the upstream language manuals for grammar and standard functions, and the local references for score's integration. Installed Qt modules, compiler support, plug-ins and graphics capabilities determine what is available in a particular build. See [[Add-ons]] for optional capabilities and [[Live coding]] for the shared code-editor workflow.
