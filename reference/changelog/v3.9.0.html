v3.9.0

v3.9.0 · October 15, 2026

All releases · Original release on GitHub · Downloads on GitHub

ossia score is a sequencer for audio-visual artists, designed to create interactive shows.

Sequence OSC, MIDI, DMX, sound, video and more, between multiple software and hardware. Create interactive and intermedia scores, script and live-code with JavaScript, ISF Shaders, Faust, PureData or C++. Leverage IoT protocols such as CoAP or MQTT, interact with joysticks, Wiimotes, Leapmotions, Web APIs and BLE sensors and integrate programs from a wealth of creative programming languages such as Structure Synth, Context-Free Art and Bytebeat. Load any kind of audio or video format and process visuals through Spout, Syphon, NDI, Shmdata or Sh4lt ; sonify large datasets with CSV and HDF5 support.

ossia score 3.9.0 is a large release: highlights are a complete 3D pipeline, new video capture, streaming and tracking devices, advances on custom user interfaces, a more customizable look, along with dozens of new protocols, synthesizers and objects.

Thanks to @edumeneses @bltzr @ogauthiersat @cbicari @samamou @darioriccio @thibaudk @aklevy for the major contributions!

Full Changelog: v3.8.2...v3.9.0

This release has been mainly developed thanks to projects happening at the Société des Arts Technologiques. It is part of the Suite SAT.
This release has benefited from a load-bearing sponsorship from Anthropic, granting free access to a Claude Max 20x plan during its development.

New features

  • 3d: a complete 3D scene pipeline, not based on Qt Quick 3D. An Asset Loader reads glTF/GLB, FBX, STL, OFF and MagicaVoxel .vox (alongside OBJ and PLY) with their lights, cameras, glTF animations and skins, and FBX node animation. Scene-graph processes filter, tag, group, switch, duplicate and transform a scene, with material overrides and everything driven from the device tree.
  • 3d: new objects include Camera, Camera Array, Camera Switch, Light, Environment, PBR Mesh, Material Override, Transform 3D, Instancer, Text to Mesh, Text to Texture, Cubemap Loader and Composer, Animation Player, and Scene Inspector, with point clouds and gaussian splats supported throughout.

Instancing is supportd, including of glTF:

instancing.webm

The entire pipeline runs on GPU, with zero CPU readback or processing, to enable massive instanced scenes that leverage compute shaders for generation and customizable render pipelines for rendering.

particles.webm

Support for volumetric (3D) textures is extensive:

volumetric.webm

as well as for custom PBR materials.

3d-2026-10-15_23.23.18.webm

The rendering system allows to render scenes with entirely user-defined scene processors: a single score can combine deferred, forward rendering, clustered forward, etc. : the engine doesn't impose or implement any specific rendering technique, they are all shader-based and part of the scores. This has been developed to enable computer graphics research in new rendering techniques, and opens the door to e.g. studies on spectral rendering, etc. Or, for more fun stuff, implementing PS1 or N64 rendering pipelines:

3d-2026-10-15_23.24.44.webm

or gaussian splats, including less standard formats than traditional 3DGS (for instanc 2DGS etc.):

splats.webm

  • about: the displayed version shows how many commits it is past the release and the branch, for example 3.8.2+42.

  • ai: librediffusion adds StreamV2V and Flux.2 Klein (with inpainting and image editing), multi-step SDXL, img2img-turbo, ControlNet, IP-Adapter, a runtime LoRA scale, and multi-step CUDA graphs with DMD2, NitroFusion and RIFE presets (shipped in the future). See https://github.com/jcelerier/librediffusion#base-models to convert models on your own machine at the right format. Requires a NVidia GPU.

  • ai: onnx: the pose detector tracks several people, with smoothing, box modes, RTMO, YOLO-pose models and an OpenPose palette. Also new: generic nodes for any ONNX model, Vocos vocoders, separation into stems, MHR body meshes and InstantHMR, SmolVLM, Gemma 3 and more LLMs and VLMs, tokenizers read from tokenizer.json, and WebNN in the web build.

  • audio: a WASAPI driver through miniaudio, now the default on Windows and following the system's default devices. Thanks @ogauthiersat!

  • automation: points snap to the timeline's magnetism (the musical grid and the points of nearby processes) while dragged or created; Ctrl disables it.

  • avnd API: section, table and strip/detail layouts, envelope editors, folder ports, folder-backed or runtime-filled comboboxes (thanks @bltzr!), geometry auxiliary buffers and textures, per-instance semantics, keyed string lists, file and save-path pickers with host-expanded placeholders, xyzw spin boxes, cubemap and render-target texture ports, and tensor ports.

  • avnd: new objects: Point Tracker (2D and 3D), Beat Tracker, Entity To MIDI, Midi Humanize, Midi Envelope, Regex, Enumerator, Array Best Match, Color display, Control to CV, Switch, Rendezvous, Serialize and Deserialize (JSON, CBOR, text, binary), String tool, Split string, Join strings, String to and from Bytes, Read File, Read File Line, Write File, and the utilities Spigot, Repeat, Mux inlets, Demux outlets, Flip Flop, Bang and Button.

  • avnd: the LED view has an RGB01 mode, taking colours as floats between 0 and 1.
  • cables: feedback is now supported in all modes, through delayed connections in the same graph: a cable that closes a loop is made a delayed cable automatically, and graphics feedback cycles render one frame late instead of blanking the output. Only a cable from a node to itself is refused. A cable's type also shows in how it is drawn, and a cable can be dragged from a port's name.

Example: reaction-diffusion, an effect implemented with compute shader geometry feedback.

  • can: new DBC-driven CAN device, browsing the .dbc databases of the library and enumerating the machine's real interfaces.
  • clap: plug-ins are also searched in CLAP_PATH, and a plug-in that marks its state dirty has it saved.
  • comment box: an Auto-reflow option wraps the text to the box's width instead of growing it sideways.
  • custom apps: generated launchers accept --debug (?debug on the web) to show the score editor next to the custom UI, and SCORE_VIDEO_DECODING_METHOD selects the video decoder.
  • devices: MIDI Controller devices build their tree from a device description, to be able to address knobs and faders directly instead of looking up MIDI CCs.
  • devices: new depth camera add-on: colour, infrared, depth and point clouds from Orbbec Femto, Gemini and Astra (also over Ethernet), Kinect v1 and v2, Azure Kinect, Intel RealSense and Luxonis OAK cameras, installable as one Depth cameras package from the package manager.
  • devices: new openzen device: LP-Research LPMS IMUs over serial and USB.
  • devices: new sysinfo device, exposing the local machine (CPU, GPU, memory, disks, battery, network, open file handles) as an ossia device with a settable refresh rate.
  • devices: new trackingprotocols add-on: OpenTrackIO, OpenXR, PosiStageNet, RTTrP and TUIO devices.
  • devices: new videoio add-on: one video input and output device for capture and playout cards, GPU-direct where the card allows it. AJA cards and V4L2 capture on Linux are built in; Blackmagic DeckLink, Magewell and NVIDIA Jetson cameras work when score is built with their respective SDKs. Deltacast, Bluefish444 will be supported later. For AJA up to 8k 60 FPs on Kona 5 has been validated.
  • devices/processes: processes now have a "Scriptable" mode which makes their parameters accessible through custom addresses in the Local device. This is by far the most important feature of this release, check the "Process cues and automations" example to learn how to use it!
  • embedded: Yocto support with the new meta-ossia repo. Enjoy ossia score as PID1!
  • fx: new versions of LFO (phase and jitter in degrees, cycles that can lock to the bars), Arpeggiator, Midi quantify, Free metronome, Rate Limiter, ADSR, Flanger, Compressor and Limiter (a lookahead brickwall peak limiter), with times set by the time chooser and able to follow the tempo. The time chooser widget has been reworked to be simpler to use: click on the indicator to switch between time in milliseconds versus beat-clock.
  • gfx: a script can render an exact number of frames, set the frame-step rate and grab frames to files, for repeatable headless renders.
  • gfx: a new Sink process runs its input at a set rate without displaying it, so a chain whose result is data, such as an AI model's output, is computed.
  • gfx: cubemap render targets and multiview rendering.
  • gfx: for capture and SDI rigs: NVIDIA GPUDirect for Video, zero-copy Vulkan capture upload, high-bit-depth planar and packed GPU encoders and a V210 decoder, GPU demosaicing of Bayer sensors, cross-stream frame correlation, bt2020-10 colorimetry, and work towards genlock support.
  • gfx: new video devices: PipeWire video input and output with zero-copy DMA-BUF, window and screen capture, GStreamer pipelines as input or output (video and audio), and gphoto2 cameras when the library is installed. The FFmpeg device (formerly Libav Output) also reads streams (RTSP, SRT), files, image sequences, cameras and screen capture, records to MP4, MKV, ProRes, DNxHD, AV1, WAV and Opus, and comes with presets.
  • gfx: shader previews can be toggled at runtime from a new Graphics toolbar.
  • gfx: window devices expose the cursor position in GL coordinates, next to the scaled and absolute ones.
  • gfx: with vsync off, a Rate of 0 (set in the config file, not through the UI to prevent GPUs to inadvertentyl burn) renders frames back to back as fast as the GPU allows. Useful for benchmarking!
  • js: a much larger API: cables, path lookup, process controls, document metadata, presets carrying a script's program and state, object colours and comments, undo stack and macros, device settings read-back, Score.select(), Score.Editor, a View object for automation and screenshots, and Util.listFiles, listDirectories, openFileDialog, saveFileDialog and removeFile.
  • js: QML scripts can read and write local files through XMLHttpRequest.
  • js: Score.Controls, Score.Triggers and Score.Conditions expose a document-wide namespace of controls, triggers and conditions, including those of child processes, also sent to remote control clients; states can address them.
  • js: Score.Editor gains hasProcessUI, showProcessUI and libraryEntries; createProcess resolves the : and : prefixes; a device's connected() can be called from QML.
  • js: scripts can build persistent, interactive QML interfaces from native score widgets and Canvas2D painting, with undoable state. Custom UIs can be docked, placed by script, or shown in a window, the side panel or the central view.
  • library: packages can ship native libraries that load on Linux, macOS and Windows.
  • midi: new MIDI display process.
  • osc: COBS framing, alongside the other framings found in the wild.
  • processes: file and folder controls save : and : relative paths, and a Faust import folder is saved relative to the library or the project.
  • processes: new carto-tcp process, receiving the point clouds that Carto from the Suite SAT streams over TCP.
  • processes: new cv add-on: computer vision objects ported from traditional Max/MSP cv.jit, rewritten without OpenCV: GPU filters (threshold, morphology, chroma key, frame difference, optical flow) and analyses (centroid, moments, histogram, corners, Hough lines), and CPU objects for 2D blobs, contours, homography and Kalman filtering.
  • processes: new FFmpeg Filter process: run any FFmpeg filter graph on audio and video, with ports and controls taken from the graph, analyzer metadata as an output, live editing, presets, and filtering kept on the GPU when on the Vulkan backend.
  • processes: path generator gets its own UI drawing the trajectories and the playing position, more trajectories, and a choice of what its output carries.
  • processes: puara: Leaky Integrator and Avalanches objects.
  • project: collect a document's media into its own folder, find missing files with an exhaustive, cancellable search, archive a project to a zip, trim media and remove the files a project no longer uses; a document can declare the platforms it runs on.
  • project: a project with missing media will allow to locate them when opening.
  • protocols: QML protocols gain Bluetooth, NFC and serial bindings, sender information on received UDP messages so replies are possible, automatic deserialization of encodings such as base64, and the OSC type tags a script asks for.
  • protocols: QML scripts can talk to SocketCAN buses, classic and FD, with Protocols.can(), and list the interfaces with Protocols.canInterfaces() (Linux).
  • protocols: QML sockets and serial ports gain STX/ETX, 1-, 2- and 4-byte little- and big-endian size prefixes and fixed-length framings, and Protocols.http() takes a full request object.
  • remote control: an HTTP server, with configurable port, address and path, serving a WebAssembly remote. Thanks @thibaudk!
  • skin: more complete skinning support, with about thirty bundled skins: editor themes (Catppuccin, Dracula, Nord, Solarized, Gruvbox, Tokyo Night...), light, greyscale and high-contrast skins, colour-blind-safe skins and skins with beautiful tight pixel fonts. A skin carries its fonts and its widget palette.
  • sound: the Sound process plays the audio track of video files (thanks @ogauthiersat !), and reads AIFC and CAF files.
  • synths: FoMo, an FM synthesizer, and Kaboom, an electronic drum machine.
  • synths: granola: polyphonic MIDI grain spawning, velocity-driven grain amplitude, a MIDI listening toggle and an active grain count output.
  • synths: the Deuterium drum machine becomes a multi-format sampler reading GIG, DLS, SF2, KORG KMP/KSF and plain audio files, with complete sampler control, trigger pads and keyboard, legato, a note-off mode and a MIDI channel filter.
  • ui: --vector-gui / --no-vector-gui for higher-quality rendering, a configurable base font size, and the Phosphor icon fonts shipped for custom UIs.
  • ui: a central view stack with a navigation bar per document, and reworked the address bar to be available in every view.
  • ui: code editors can now be docked or also used as central view.
  • ui: right-clicking the XY pad opens spin boxes, so a coordinate can be typed or pasted.
  • ui: scoring internal processes now behaves exactly like scoring device tree parameters, including support for tweening, etc. Simply drag a parameter to a state, etc.
  • wasm: the LTC, Granola, bendage, Airwindows, cv, ONNX and Deuterium add-ons are available in the web build.
  • wasm: the web build gets camera input (getUserMedia and WebCodecs), audio input, drag-and-drop media import, asynchronous Load and Save As, documents opened from the page URL, zip project archives, persisted settings and local-storage backups, and the start screen with its online examples.
  • windows: a Windows arm64 build.
  • ysfx: a JSFX in the library is described by its own header: description, author, tags and license.

Improvements

  • 3d: fulldome output offers the four fisheye projections: equidistant, equisolid, stereographic and orthographic.
  • bendage: the JPEG node uses libjpeg-turbo, about five times faster at 1080p; Airwindows plug-ins get proper parameter widgets.
  • jk: jk filters understand jq literals, arithmetic, comparisons, //, ? and the builtins, with jq's operator precedence.
  • ndi: NDI sends every format it can encode from the GPU without a copy. A source is chosen by name and previewed before connecting, with colour, receive format and deinterlacing settings; all eleven receive formats are decoded, including the alpha of UYVA and PA16. NDI performanc is greatly improved and has been tested for instance transmitting 8K video.
  • ndi: the newest NDI runtime installed is loaded. It used to mistakenly be the oldest.
  • ai: onnx models load and run on a worker thread instead of the audio thread, a frame that fails no longer disables the node, and a model that cannot be built does not take the others down.
  • spat: SpatGRIS, SPAT and ADM-OSC devices take a source index offset.
  • leapmotion: one Leap Motion device per sensor.
  • data: large HDF5 and CSV columns are imported as one sampled curve segment.
  • lsl: LSL outlets are named after their UID.
  • GBAP: in Voronoi mode a node fades in at the edge of its zone, instead of a sharp jump.
  • synths: Synthimi and Kabang envelope times are time choosers, and Kabang's UI is redesigned with drum strips.
  • 3d: the Model Display light no longer moves with the transport, and models whose normals face away from the light are lit.
  • app: --script starts on a document with nothing modal in the way.
  • app: a redesigned start screen with templates, examples (including those published on the documentation site), project info, archives and an about page listing the license of every bundled component. It covers the main window, returns when the last document closes and is reachable from the Help menu. Thanks @samamou !
  • audio: a sound file at a different rate than the device, or above 4GB, is streamed instead of decoded entirely into memory, and plays at the right pitch; a document's master volume is applied when it is opened.
  • audio: the audio engine stays alive across documents, which should reduce errors about audio devices, and a soundcard change while a document is loaded is survived.
  • audio: the PipeWire back-end adapts to graph quantum and rate changes instead of skipping cycles, and detects a graph that schedules nothing.
  • automation: resizing an interval with many automations no longer rebuilds every state on each mouse move (0.5 to 1.4 s per move before).
  • avnd: a Bang or a Button drives any toggle for one tick, and toggles accept numbers.
  • avnd: an enum control set by name or number from a state or a script takes that value, enum ports start at their declared default, and a name received by message stays a name.
  • avnd: every built-in object has a functional category and a description, and every port has a name.
  • avnd: Prompt Composer's keywords are a list, and each weight port follows its keyword when the list is reordered.
  • avnd: two-, three- and four-component and colour controls carry their unit (cart2D, cart3D, rgb).
  • dataflow: a single number sent to a vector or colour control is rescaled into the control's range.
  • devices: the device dialog is sorted, with Video in, Video out and Media categories, and joysticks plugged in while it is open appear.
  • explorer: large and small numbers are no longer shown in scientific notation.
  • flatpak: Wayland support.
  • gfx: ISF event inputs and Faust buttons fire on impulses from cables and messages.
  • gfx: resizing an output or inserting a node keeps feedback, simulations and persistent passes instead of restarting the graph.
